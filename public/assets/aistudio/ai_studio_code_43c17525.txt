# Архитектурная спецификация и полное ТЗ проекта «Турнир 26-27» (Tournament Poster Studio & Live Match Center)

Этот документ содержит полное описание архитектуры, моделей данных, алгоритмов расчёта статистики, генератора графических постеров (PNG/HTML), PWA-конфигурации и облачной синхронизации Firebase Firestore. Используйте этот файл как готовый промпт или техническое задание для быстрого старта аналогичного спортивного/турнирного проекта.

---

## 1. Назначение системы
Универсальное веб-приложение (React + TypeScript + Tailwind CSS + Vite PWA + Firebase Firestore) для организаторов спортивных турниров (мини-футбол / футзал / футбол 8х8 и др.), объединяющее:
1. **Управление мульти-турнирами**: длительные чемпионаты (круг / группы + плей-офф) и однодневные кубки.
2. **Реестр команд и заявок**: базовые заявки, трансферное «окно доборов», амплуа игроков (`FIELD` — полевой, `GK` — вратарь), игровые номера, статусы, штрафные очки команд, масштабируемые логотипы.
3. **Матч-центр и расписание («Матчи»)**: создание игровых дней в 2 шага, ведение живого протокола прямо с телефона у кромки поля («На поле»), учёт вратарей по таймам (`1Т` / `2Т`), голов (с автором, ассистентом, пенальти и полем «Кому забили (ВР)»), автоголов, жёлтых и красных карточек, технических побед (`ТП 5:0`) и серий пенальти.
4. **Аналитика и таблицы («Статистика»)**:
   - Турнирная таблица (очки, личные встречи при равенстве очков, разница мячей, форма за 5 игр, линия плей-офф).
   - Интерактивная сетка плей-офф (1/4, 1/2, матч за 3-е место, финал) с автопосевом или ручной жеребьёвкой и автопроходом победителей.
   - Таблица бомбардиров и ассистентов (`И`, `Г (пен.)`, `Ассист`, `Г+П`).
   - Таблица вратарей (`И`, `ПМ` — пропущено мячей, `КН = ПМ / И` — коэффициент надёжности, `Сух.` — матчи на ноль, `ЖК`, `КК`).
   - Таблица дисциплины (автоматический контроль дисквалификаций по порогу ЖК: 2, 3, 4 или 5 карточек и красным карточкам).
   - Выгрузка любой таблицы в CSV.
5. **Генератор вещательной графики (Broadcast Poster Engine)**:
   - Живое превью и рендер 100% чётких PNG-постеров через нативный **HTML5 2D Canvas API** (без багов `foreignObject`/CORS) и автономный HTML-код.
   - 6 режимов постеров: `schedule` (Расписание), `results` (Результаты), `standings` (Таблица), `scorers` (Бомбардиры), `goalkeepers` (Вратари), `bracket` (Сетка кубка).
   - 3 формата холста: `1:1` (1080×1080), `4:5` (1080×1350), `16:9` (1920×1080) и 6 визуальных тем оформления.
6. **Облачная работа вдвоём (Firebase Auth + Firestore) + Offline-First PWA**:
   - Мгновенный старт из `localStorage` без обязательной регистрации.
   - Авторизация через Google (`signInWithPopup` с автоматическим фолбэком на `signInWithRedirect` для мобильных браузеров и защитой от встроенных WebView Telegram/WhatsApp).
   - Совместный доступ владельца турнира (`ownerId`) и напарников по списку Gmail (`collaboratorEmails`) в реальном времени (`onSnapshot`).

## 2. Технологический стек и структура модулей

- **Frontend**: React 19, TypeScript, Tailwind CSS v4 (`@tailwindcss/vite`), `lucide-react`.
- **PWA**: `vite-plugin-pwa` (Workbox, `registerType: 'autoUpdate'`, `skipWaiting`, `clientsClaim`).
- **Backend (опционально)**: Express (`server.ts`) — раздаёт SPA и содержит маршрут `POST /api/fetch-sheet` для чтения CSV из Google Таблиц.
- **Cloud BaaS**: Firebase v13 (`firebase/auth`, `firebase/firestore`), линтинг правил через `@firebase/eslint-plugin-security-rules`.

### Ключевые модули:
- `src/types/tournament.ts` — все типы данных (`TournamentRecord`, `Team`, `Player`, `MatchItem`, `MatchEvent`, `StandingsRow`, `PlayerStatRow`).
- `src/utils/standings.ts` — расчёт турнирной таблицы (с тай-брейком личных встреч), статистики полевых игроков и вратарей (`ПМ`, `КН`, `Сух.`), экспорт в CSV.
- `src/utils/playoff.ts` — генерация сетки кубка (1/4, 1/2, 3-е место, финал), автопроход победителей, расчёт координат карточек и SVG-линий для постера.
- `src/utils/canvasPosterExport.ts` — 2D Canvas рендерер всех 6 типов постеров в PNG высокого разрешения.
- `src/lib/firebase.ts` и `src/lib/firestoreSync.ts` — авторизация Google (Popup + Redirect), двухпоточные подписки `onSnapshot` (собственные + расшаренные документы), пакетная синхронизация.
- `src/components/LiveMatchModal.tsx` — живой протокол матча с телефона (переключатель `1-й тайм` / `2-й тайм`, выбор вратаря на каждый тайм, выбор «Кому забили» при голе/автоголе).

## 3. Ключевые алгоритмы бизнес-логики

1. **Тай-брейк в турнирной таблице**: Очки → Очки в личных встречах → Разница мячей в личных встречах → Общая разница мячей → Победы → Забитые мячи.
2. **Учёт вратарей по таймам и «Кому забили»**:
   - В матче хранятся `homeGkHalf1Id`, `homeGkHalf2Id`, `awayGkHalf1Id`, `awayGkHalf2Id`, а в каждом событии гола/автогола — `half` (`1 | 2`) и `concededGkId`.
   - Если в заявке команды ровно 1 активный вратарь, он подставляется автоматически в оба тайма и получает явку во всех завершённых матчах команды.
   - Технические поражения (`ТП 5:0`) не начисляют вратарям ни пропущенных мячей (`ПМ`), ни сухих матчей (`Сух.`).
3. **Сухие матчи («Вариант А») и Коэффициент надёжности (`КН`)**:
   - Если команда пропустила за матч `0` голов (не ТП), каждый сыгравший в матче вратарь этой команды получает `+1` в `Сух.`.
   - Если команда пропустила `>= 1` гола, `Сух.` не получает никто из вратарей этой стороны, а конкретные `ПМ` записываются на того вратаря, который защищал ворота в соответствующем тайме/эпизоде (включая автоголы своей команды).
   - Рейтинг вратарей сортируется по `КН = ПМ / И` (по возрастанию), затем по `Сух.` (по убыванию) и `И` (по убыванию).
4. **Двухпоточная синхронизация Firestore (`ownerId` + `collaboratorEmails`)**:
   - В каждом документе `tournaments`, `teams` и `matches` хранятся `ownerId` и массив `collaboratorEmails` (в нижнем регистре).
   - Клиент параллельно слушает `where('ownerId', '==', uid)` и `where('collaboratorEmails', 'array-contains', email)` и объединяет документы по `id`.
   - Напарник может редактировать составы, расписание и живые матчи; завершённые матчи (`status == 'finished'`) защищены от случайного изменения и доступны для правки только создателю турнира.
